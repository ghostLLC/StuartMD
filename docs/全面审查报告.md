## 一、安全（Critical / High 优先）

### Critical

**C1 插件加载 = 无沙箱 `new Function` + 全量 `window`/`document` + 全量 Tauri IPC**
- `web/js/plugins.js:60`，`boot()` 自动 `loadAll()`
- 攻击：向 `%APPDATA%\StuartMD\plugins\` 丢一个 `.js` → 下次启动即 RCE，可写启动项、读密钥、改 `base_url` 外传 API Key
- 修复：禁止自动加载；首次启用需确认 + 显示路径/哈希；iframe/Worker 隔离；能力白名单

**C2 `stuart_read_file` / `stuart_write_file` 无路径约束**
- `fs_api.rs:437-495` 任意路径读写（≤8MB）
- 是所有前端 XSS/插件问题的放大器 → 启动目录写入 = 持久化 RCE
- 修复：对话框在后端发起并返回能力令牌；会话内「用户打开/保存过的路径」白名单；拒绝 UNC

### High

| ID | 问题 | 位置 |
|----|------|------|
| H1 | contenteditable **粘贴未消毒** → 粘贴即 XSS | `app.js` 无 `paste` 处理 |
| H2 | DOMPurify **未打包**，生产走手写白名单；允许 `<style>`/`style` 属性；innerHTML 双解析有 mXSS 面 | `app.js:270-407` |
| H3 | AI `base_url` 可被改到任意主机，DPAPI 密钥被 Bearer 外传 | `ai_chat.rs:466-486, 655+` |
| H4 | `sanitizeUntrustedMarkdown` 是正则黑名单（项目自己的路线图明令禁止） | `agent-api.js:24-31` |

### Medium（择要）
- M1 设置里 `ai.providers[].id/label` 未转义 → 二阶 XSS（`ai-ui.js:364`）
- M2 `stuart://anchor?file=` 可打开任意路径（companion 链）
- M3 `reveal_in_explorer` 可开 UNC → NTLM 哈希泄露
- M4 CSP 实际关闭（`csp: null` + `unsafe-eval` + `connect-src https:`）
- M5 知识上下文 XML 属性未转义 → 提示注入放大
- M6 记忆无来源标记，可被文档/插件写入后跨会话注入提示

### 已经扎实（避免误报）
链接策略、`stuart_open_url`、AI 输出转义渲染、Mermaid strict、PDF 批注导出转义、`stuart_resolve_asset` 路径围栏、DPAPI 密钥不回传、FTS5 转义、diff_guard 哈希校验。

## 三、架构（4.5 / 10）

### 核心病根（也是内容丢失反复出现的原因）

1. **每次块提交都对全文做有损 split/join**（`commitBlockSource` → `joinBlocks(split(text))`）  
   实证丢失：硬换行（行尾双空格）、尾换行、首尾空行、CRLF、仅空白行。  
   `doc-stats.js:36` 的 `.replace(/\s+$/,"")` 是硬换行杀手。
2. **写文件无序**：`doAutoSave` 与 `saveFile` 并发 `write_file`，旧内容可能最后落盘；`saveFileAs` 清 dirty 不比对 rev。
3. **块身份 = 数组下标**，漂移后静默丢编辑（`commitBlockSource` return false 且无提示）。
4. **`openDocumentRespectingMode` 未定义**（`app.js:3420`）→ 丢文件到标签栏会 ReferenceError。
5. **`save_draft` 在 Tauri 桥不存在** → “零丢失日志”是空的。

### 模块边界
- **好的范式**：`core/doc-stats`、`open-policy`、`settings-schema`、`tauri-bridge`、`ai-service`（纯逻辑 + 可测）
- **债务**：`app.js` ~6.4k 行上帝对象；`window.pywebview` 假名桥接；`pdf-viewer.js` 第二个单体
- **死代码**：rag/ + memory M5 + context 金字塔 + diff_guard ≈ 3800 行 Rust 与 5 个 UI 模块「编译但未加载」；`dist-installer/` 90+ 个安装包约 2.5GB 在树内

### 测试
约 90% 是字符串存在断言或 mock 复刻；真正跑逻辑的只有 `core-smoke.js` 与少量 Rust 单测。  
**缺**：split/join 往返金样、编辑管线、IPC 集成、CI。

### 目标架构（增量，不推倒）
```
core/doc-model.js    # 字节 span，编辑用 splice，禁止 join(split(text))
core/write-coord.js  # 每路径单飞写队列 + 代数 token
state/document-store # 唯一真源 {path,text,rev,dirty,history}
editor/*             # 从 app.js 抽出
ipc/StuartIPC.js     # 改名，pywebview 留一版别名
```

**关键设计：** 全文为真源，块只是 span；改块 = 原文 splice。块外字节不变，硬换行/CRLF/空行由构造保证。

## 四、合并后的优先修复路线

4. **编辑丢失必须 toast**，禁止静默丢弃  
5. 修 `openDocumentRespectingMode` 一行 bug  
6. 实现 `save_draft` 或删掉假日志、缩短 autosave  
7. **粘贴消毒**（H1）+ **禁止插件自动执行**（C1 最小集）

## 六、结论

- **漏洞：** 有可利用链（插件 / 文件 API / 粘贴 XSS / 洗白不全），必须按 C1→C2→H1→H2 顺序收口。  
- **理念：** 大方向正确，失分在收尾（emoji、残留、术语、示例版本、入口密度）。  
- **架构：** `core/` 拆分方向对；编辑管线的「有损全文重写 + 无序写」是内容丢失类 bug 的总源头，P0 做完这一类会绝迹。  
- **不要做的事：** 不要大爆炸重写；不要继续在 app.js 里打防御补丁掩盖 span/写队列问题。

**建议下一版（3.5.x）主旋律：** 「数据正确性 + 安全止血」= P0 #1–#7 + 设计 Must 1–4，而不是新功能。
